# Queue Lab

Материалы урока DreamTeam Development «Rate Limiting на Python: ограничение запросов и алгоритм Token Bucket».

Видео: https://youtu.be/-mm9ttnVu6M

Сообщество: https://vk.ru/dreamteamdev  
Связь: https://t.me/yettidevelop

Работающая офлайн-модель очереди на Python 3.10+. Никаких сетевых запросов.

```
python model.py
python -m unittest -v test_model.py
python demo.py
```

Для окна `demo.py` нужны Tkinter и Pillow (`python -m pip install Pillow`).
Ядро и тесты используют только стандартную библиотеку.

Четыре эксперимента: NORMAL, OVERLOAD, BOUNDED, LIMITED. На каждый поступает детерминированный поток задач. Четыре обработчика ждут условную зависимость 200 мс, то есть верхняя теоретическая пропускная способность — 20 задач/с. В перегрузке приходят 30 задач/с.

Все времена — модельные. Занятый обработчик не равен занятому CPU. Программа не измеряет системную загрузку, не реализует HTTP/TCP и не является защитой реального сервера. Поле p95 считается по завершённым задачам; ожидающие и отклонённые показываются отдельно. LIMITED использует token bucket с ёмкостью 1: фактический допуск при дискретном потоке может быть ниже установленной верхней границы 18 задач/с.

Генератор вызывает только методы модели. Добавления адреса назначения, сетевых сокетов и внешнего генератора нет.

Материалы для проверки концепций:
- https://docs.aws.amazon.com/wellarchitected/2022-03-31/framework/rel_mitigate_interaction_failure_fail_fast.html
- https://d1.awsstatic.com/builderslibrary/pdfs/avoiding-insurmountable-queue-backlogs.pdf

Модель ограничена постоянной стоимостью работы, фиксированным пулом и отсутствием вариативности. Результаты не предсказывают характеристики настоящего сервера.
